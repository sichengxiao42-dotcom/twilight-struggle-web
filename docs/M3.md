# M3：双人房间与断线重连

## 运行与邀请

```bash
npm ci
npm run dev
```

前端监听 `0.0.0.0:5173`，游戏服务器监听 `0.0.0.0:3001`。前端通过 Vite 的 `/socket.io` 代理访问游戏服务。

1. 同一台设备可打开两个独立标签页测试，分别选美苏。
2. 两台设备联机时须位于同一局域网，用主机的局域网 IP 打开前端，例如 `http://192.168.1.20:5173`；请换成实际 IP，并按系统要求允许这两个服务的网络访问。
3. 选择阵营并创建房间，把邀请链接发给另一方；链接包含房间号和对方阵营，接收者点“加入房间”。
4. 双方入座后才能操作。各自只看到自己的手牌；等待对方期间按钮与地图目标不可操作。
5. 连接中断后自动重新加入；刷新同一标签页也会读取该标签页保存的恢复身份。可通过“恢复上次房间”手动恢复。
6. 网络操作确认超时可点“重试待确认操作”。请求编号保持不变，不会把已结算操作执行第二次。

邀请链接没有身份恢复令牌。不要把自己标签页保存的身份当成邀请信息交给其他人。返回本地保留恢复身份，再加入其他房间会覆盖本标签页保存的上次身份。

生产运行已支持同一 Node 服务提供网页与联机：构建后执行 `npm start`。部署准备见 [DEPLOYMENT.md](DEPLOYMENT.md)。尚未部署到公网。局域网地址不是公网网站地址；跨网络访问需要后续部署。前后端分开托管时，在构建前设置 `VITE_SERVER_URL` 为游戏服务器地址；服务器可通过逗号分隔的 `ALLOWED_ORIGINS` 配置允许的前端来源。

## 权威状态与视图

- `RoomStore` 为每个房间保存完整引擎状态、阵营身份哈希、在线连接、局面版本、请求去重记录及动作序列。
- 操作方由服务端连接身份决定，客户端不能在动作里指定另一阵营；输入还会经过动作结构和引擎规则双重校验。
- `viewFor` 只选取公开字段。客户端拿不到 seed、随机数游标、牌库顺序、待执行任务或行动开始时的内部快照。
- 对方手牌仅发送张数。CIA 效果生效时，美国按规则可以看到苏联手牌；剑桥五杰和其他私有决策只发给决策方。
- 单方已选头条不发给对手；拥有对应太空特权的一方例外。双方选完后由引擎通过公共日志揭示。
- 服务端逐连接发送各自视图，不广播完整 GameState。错误请求不改变状态，也不推进随机数。
- 已占用阵营保留给原身份；同一恢复令牌在新连接恢复后，旧连接被断开。未知令牌不能接管席位。

## 断线与数据边界

房间保存在单个服务进程的内存中：可以恢复短暂断网与同一标签页刷新，**不能在服务重启后恢复**。两方均离线超过 24 小时的房间可在后续创建房间时清理，房间上限为 200。没有账号、观战、多进程共享状态或持久化存档。

恢复身份使用 `sessionStorage`，不会进入邀请链接。同一浏览器的两个独立标签页可分别持有不同阵营；新标签页不会自动继承其他标签页的身份。关闭标签页、清除站点数据或浏览器限制存储，都可能使身份无法恢复。

客户端断线时禁止操作，不离线模拟或乐观修改局面。服务端已接受而确认消息丢失的请求，可用原编号安全重试；旧局面版本的未接受请求会被拒绝并刷新视图，需要玩家重新选择。

中晚期和完整终局仍未实现；房间内进行的是 M2 的前三回合流程。中文卡图沿用现有素材索引。

## 验证

`npm run check` 包含核心规则测试、视图泄露测试、房间身份与版本校验测试和真实 Socket.IO 集成测试。

集成测试在随机本地端口启动真实 HTTP / WebSocket 服务，连接两个客户端，从布点、头条和事件决策一直完成第 3 回合；途中断开并用恢复令牌重新连接，还检查阵营占用、重复请求、过期版本和每次下发的手牌视图。

浏览器视觉验收与两台实体设备验收尚未完成；双客户端测试使用真实网络传输，但不替代手机浏览器排版检查。
