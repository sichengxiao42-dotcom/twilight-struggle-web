# 《冷战热斗》网页版 · 项目企划书

> 版本 v0.1 · 2026-10-19 · 状态：立项草案

## 1. 项目概述

《冷战热斗》（Twilight Struggle，GMT Games 出版，Ananda Gupta / Jason Matthews 设计）是一款双人卡牌驱动战略桌游。玩家分别扮演美国和苏联，在 1945–1989 年的 10 个回合里争夺全球影响力。

本项目要做一个**浏览器即开即玩的网页版**：

- 双人在线对战（房间号邀请），也支持同屏热座。
- 完整实现豪华版（Deluxe Edition）基础规则与 110 张卡牌事件。
- 界面以中文为主，保留英文卡名。
- 规则引擎与界面分离，可回放、可测试，后续可接 AI 对手。

### 1.1 为什么做

| 现状 | 痛点 | 本项目的做法 |
|---|---|---|
| TTS 模组 | 要买 TTS，所有规则手动执行，容易出错 | 引擎自动结算，非法操作直接拦截 |
| 官方 Playdek 数字版 | 要买、要装客户端，中文和社区功能有限 | 网页打开即玩，中文优先 |
| 线下实体 | 要凑人凑时间，一局 2–3 小时 | 异步对局，断线可重连 |

## 2. 目标与非目标

**目标（v1.0）**
1. 完整规则：头条阶段、行动轮、OPS（放置影响力 / 调整 / 政变）、太空竞赛、DEFCON、军事行动、计分、中国牌和所有胜利条件。
2. 早、中、晚三期共 110 张卡牌事件全部用代码实现，并有单元测试。
3. 双人在线对战：服务器权威校验，按阵营隐藏手牌，断线重连。
4. 完整对局日志，可从种子 + 动作序列复盘。

**非目标（v1.0 不做）**
- 零回合（Turn Zero）、推广卡、变体规则（可作为后续扩展）。
- 匹配天梯和账号体系（v1 只用房间号 + 临时身份）。
- 原生 App。

## 3. 用户与核心体验

- **核心用户**：玩过实体或 TTS 版的中文玩家，想低门槛在线开局。
- **次要用户**：新手。需要规则提示、可执行操作高亮、事件说明悬浮框。

**核心流程**：创建房间 → 分享链接 → 选阵营 → 设置阶段放置影响力 → 每回合头条 → 行动轮出牌（选事件或 OPS）→ 回合结束检查 → 终局。

**体验原则**
- 每一步都告诉玩家“现在能做什么”：可放置的国家高亮，非法操作给出原因。
- 关键结算都要说明：政变骰点、调整修正值、计分明细逐条列出。
- 撤销：结算前的选择可以撤销；涉及掷骰或暴露信息之后不可撤销。

## 5. 技术方案

### 5.1 技术栈

沿用 `da-vinci-code-web` 已经验证过的栈，减少学习成本：

- **语言**：TypeScript（严格模式），npm workspaces 单仓多包。
- **前端**：React 19 + Vite。地图用 SVG 渲染（可缩放，点击区域精确）。
- **后端**：Node.js + Socket.IO，房间内保存权威状态。
- **测试**：`node:test` + `tsx`。引擎覆盖率目标 ≥ 90%。
- **部署**：同一个 Node 服务托管静态前端和 WebSocket（Render / Fly.io 均可）。

### 5.2 目录结构

```
packages/shared      阵营、地区等公共类型，Socket 协议
packages/game-core   纯函数规则引擎（不依赖 DOM / 网络）
  src/data/          地图（84 个国家）与卡牌元数据
  src/rules.ts       控制、DEFCON 限制、政变等规则函数
  src/state.ts       GameState 与开局
  src/events/        （待建）每张卡的事件实现
apps/web             React 前端
apps/server          Socket.IO 服务端
tools/               素材导入等脚本
docs/                企划书、规则摘要、素材说明
```

### 5.3 规则引擎设计

- **状态 + 动作 → 新状态**：`apply(state, action) → state`，是纯函数。所有随机数来自带种子的 RNG，因此任何一局都能用 `seed + actions[]` 完整重放，方便复盘、测试和排查 bug。
- **待决策栈（Decision Stack）**：《冷战热斗》大量事件需要玩家中途做选择，例如“移除对手 4 点影响力，每国最多 2 点”。引擎用一个“待决策”栈表示当前该谁、在哪些合法选项里选。前端只负责渲染这个栈，不需要知道任何规则。
- **事件实现**：每张卡一个模块，导出 `canPlay`、`resolve` 和持续效果钩子。持续效果（如 NATO、遏制政策、红色恐慌）挂到 `modifiers` 上，由 OPS 计算、政变、放置等环节统一查询。
- **隐藏信息**：服务端用 `viewFor(state, side)` 裁剪状态（对手手牌只显示数量，牌堆顺序不下发）。
- **合法动作枚举**：`legalActions(state, side)` 同时供 UI 高亮、服务端校验和将来的 AI 使用。

### 5.4 前端

- 世界地图：SVG 底图 + 每国一个可点击区块，显示稳定度、战场标记、双方影响力和控制状态。
- 信息面板：DEFCON、VP、军事行动、太空竞赛、回合 / 行动轮轨道。
- 手牌：有本地素材时显示原版卡图（见第 6 节），否则显示自制文字卡。
- 日志区：按回合折叠，点击条目可高亮相关国家。

## 6. 中文素材与仓库

2026-10-19，项目所有者确认只使用中文素材，并要求将图片上传到私有仓库。当前仓库提交 55 个中文模组图片文件，以及 #1–110 卡牌索引，包含中文地图、卡背、标记和辅助图。英文图片仅作本地备份。

来源为 [冷战热斗中文版模组 2793711137](https://steamcommunity.com/sharedfiles/filedetails/?id=2793711137)，尺寸和 SHA-256 见 [ASSET_INVENTORY.json](ASSET_INVENTORY.json)。本作署名和版权归属保持原样，模组图片的纳入不代表取得公开发行授权。

协作者拉取仓库后即可使用中文卡图；无需订阅 TTS 模组或运行导入脚本。详见 [ASSETS.md](ASSETS.md)。地图和标记图片尚待接入棋盘交互，卡面译文仍需核对官方规则。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 素材公开发行范围尚未确定 | 高 | 当前使用私有仓库；公开上线前明确素材使用范围 |
| 卡牌事件多、交互复杂、例外条款多 | 高 | 待决策栈统一建模；每张卡至少一个测试；对照规则书和 FAQ 逐条核对 |
| 规则理解偏差 | 中 | `docs/RULES.md` 标注出处，所有数据以实体规则书为准复核 |
| 地图相邻关系数据量大（84 国） | 中 | 一次性录入，并用测试校验对称性和连通性 |
| 业余开发周期长、中途搁置 | 中 | 每个里程碑都可独立游玩，小步交付 |
