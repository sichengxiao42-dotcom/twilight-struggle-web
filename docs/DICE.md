# 点击掷骰

本地与联机对局均启用 `manualDice`。政变、调整、太空尝试、战争事件、泥潭／捕熊陷阱、奥运会和首脑峰会需要投骰时，会进入 `DICE_ROLL` 阶段。

玩家点击浮窗内自己的骰子后，规则引擎才生成 1–6 的点数。双方投骰时由双方依次点击；点数全部显示后，由第一位投骰者点击“继续结算”。地图变化、成功判定和奖励在确认后应用。机器人自动掷自己的骰子并确认。奥运会修正后同点时重新请求一组骰子。

客户端只提交 `ROLL_DICE` 或 `CONTINUE_DICE`，不能指定点数。联机沿用服务端权限、版本检查、请求去重和身份恢复；重连保留已投出的值，掷骰后清空撤销历史，避免重投。浮窗不能用 Esc 或遮罩跳过，断线时会等待身份恢复。

## 规则中的暂停与继续

`dice.ts` 在真正读取随机数前暂停动作。`apply` 保留私有的动作起始状态和原始指令，在玩家确认后按已批准的投骰组数重放同一个确定性事务，直至下一个投骰请求或动作完成。前缀中的弃牌、洗牌、事件等随机调用仍使用同一 RNG 序列。重复执行发生在副本中，最终只发布一次状态，不会多扣行动点、多弃牌或多记出牌。

等待投骰的公开状态可展示已打出的牌与事件信息；私有起始状态、原始指令、随机种子、游标和重放计数不进入 `PlayerView`。只有实际点击后的骰点会出现在公开视图与最近 100 组投骰记录中。纯规则测试可不启用 `manualDice`，继续使用原本的自动结算路径。

## 验证

- 对比自动与手动投骰的完整种子对局，逐动作校验地图、RNG 游标、牌区、日志和公开出牌完全一致。
- 覆盖政变等待、太空、战争、陷阱、双方调整与奥运会同点重投。
- 16 个机器人种子对局启用点击掷骰流程后仍可正常结束。
- 真实 Socket.IO 验证阵营权限、拒绝伪造点数、同请求去重、重连恢复点数与不可撤销投骰。
